- `RTVIObserver` sends bot output it used to hold back or leak: output that will not be spoken is sent at once instead of waiting for the bot to start speaking; spoken output is sent with `bot_speaking_enabled=False`, since the bot's speaking state is tracked whatever the flag and only its messages follow it; an interruption drops the output queued for the interrupted response; and a progress transform's empty strings are kept instead of falling back to the original text. The observer also keeps at most 10,000 frame ids for its dedup, none for audio whose level message is off, and those of audio whose level message is on in a second dedup of the same bound, so that audio cannot push out the id of a frame the output transport has yet to push again.
