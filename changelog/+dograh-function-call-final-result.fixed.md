- A function call's deadline and settlement now follow its final result. A progress update (`is_final=False`) from an async function call no longer cancels the call's timeout, so a call that reports progress and then stalls is still cancelled at its deadline. A call whose final result was already broadcast, and whose handler is still unwinding when it is cancelled, has its handler cancelled but is not settled a second time: no `FunctionCallCancelFrame` and no `on_function_calls_cancelled` report. `UserIdleController` tracks outstanding calls by `tool_call_id` and settles one only on its cancel or its final result, so a progress update, a result for an id it never saw (the built-in cancel tool's), or a cancel after a final result no longer lets the idle timer start while a call still runs.
