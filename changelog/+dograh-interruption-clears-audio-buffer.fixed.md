- `BaseOutputTransport` discards the partial output chunk on an interruption whether or not the bot has started speaking, so audio of an interrupted response that never filled a chunk no longer prefixes the next response. Playing a `TTSStoppedFrame`, or the silence that ends a speech stream, no longer clears that buffer: by then it holds the next response's audio, of which up to one chunk was cut. Only the queue-empty timeout still discards a stale leftover.
