- `AWSNovaSonicLLMService` no longer resets the whole session over one tool call; an empty argument string runs the call with `{}`, as the chat-completions loop does. A `toolUse` event whose arguments do not parse is now skipped with the warning the chat-completions loop logs, "Failed to parse function call arguments", and one that names a function nobody registered now goes to `run_function_calls`, whose missing-function path answers the model with a tool result, as every other LLM service does. Both used to raise out of the event handler into the receive loop, which pushed an error and rebuilt the session mid-call. `AWSNovaSonicUnhandledFunctionException`, which nothing raises any more, is removed.
