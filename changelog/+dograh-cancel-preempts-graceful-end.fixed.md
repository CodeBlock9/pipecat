- A cancel requested while an `EndFrame` or `StopFrame` is still on its way to the end of the pipeline now preempts that wait: the worker hands the `CancelFrame` to the pipeline directly, waits for it under the cancel's own timeout, and fires `on_pipeline_finished` with it. The cancel used to go onto the push queue behind the ending frame, and the push queue's task was the one waiting, so a graceful end that never landed could not be cancelled by anything, the idle monitor and an outer cancellation included, and the worker never finished. Without a cancel the graceful wait still has no bound, so a farewell plays out in full. `on_pipeline_finished` now fires once per worker, for whichever terminal frame lands first.
