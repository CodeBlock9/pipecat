- `BaseOpenAILLMService` — and so `AzureLLMService` and every OpenAI-compatible service — accepts `request_timeout`, `turn_request_timeout` and `max_client_retries`; `AnthropicLLMService` accepts `request_timeout` and `max_client_retries`. All default to `None`, which leaves the SDK's own behaviour in place. `request_timeout` reaches the HTTP client, so an `httpx.Timeout` bounds time-to-first-token and then each inter-chunk gap: a trickling stream is tolerated, a stopped one is not. `turn_request_timeout` applies per request on the streaming completion alone, so one service instance can hold a short deadline for a conversational turn and a longer one for out-of-band inference.
