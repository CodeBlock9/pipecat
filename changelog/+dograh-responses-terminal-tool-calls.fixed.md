- `OpenAIResponsesLLMService` (WebSocket) no longer runs a function call whose arguments never finished streaming when a response ends in `response.failed`, `response.incomplete` or an `error` event; like the HTTP variant, it runs only the calls that completed. It reports the server's own failure message or truncation reason, read from the Responses API's `error` and `incomplete_details` rather than a Realtime API field that is never present, and it coalesces a null usage count to 0 instead of losing the finished call and the previous-response state to a validation error. Both variants skip a call whose arguments do not parse, with a warning, instead of running it with empty arguments.
