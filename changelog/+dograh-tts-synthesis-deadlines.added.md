- `TTSService` accepts `synthesis_first_chunk_timeout_s` and `synthesis_chunk_gap_timeout_s` (both `None` by default, which leaves synthesis unbounded), plus `synthesis_timeout_burst` and `synthesis_timeout_window_s`. The first bounds the wait for a synthesis's opening audio and the second each gap after it; on expiry the generator is closed, a `TTS synthesis timeout` line is logged and a non-fatal error is pushed, so the call loses a sentence rather than the line. `synthesis_timeout_burst` expiries inside the window push a fatal error instead. Websocket-shaped services deliver audio through their own receive loop rather than from the generator, so the same deadline is also armed per context when the request is sent and cleared by that context's first `TTSAudioRawFrame`.
